# value-investing-analyst 需求清单（REQUIREMENTS）

> 版本：v1.1 · 建立日期：2026-09-10（周四） · 来源：skill 全面评审 + 两批回测复盘
> 用途：作为 skill 迭代的单一需求事实源。每条需求有唯一 ID、优先级、动因、价值、验收标准与状态，回测批次收官时同步更新状态。
> 与其他文件的关系：`MAINTENANCE.md` 讲"怎么改"，`backtest/observations.md` 讲"发现了什么"，本文件讲"为什么要做、要做什么、做到什么程度算完"。

---

## 0. 使用约定

状态取值：`todo` 未开始 · `doing` 进行中 · `verify` 待回测验证 · `done` 已完成并通过验收 · `drop` 放弃（须写原因）。

优先级定义：

| 级别 | 含义 | 判定标准 |
|---|---|---|
| P0 | 阻断级 | 不做，现有结论本身不可信（数据错、排雷漏、假阳性未验证） |
| P1 | 框架级 | 不做，约一半公司类型只能输出"观察/太难" |
| P2 | 闭环级 | 不做，系统会退化而无人发现 |
| P3 | 价值级 | 让"有价值的三件事"从骨架变成完整交付 |
| P4 | 工程债 | 不影响正确性，影响可持续性 |

来源标记：`A` 最重要的三件事缺口（A1 数据真实性 / A2 不错买优先 / A3 可证伪闭环） · `B` 最有价值的三件事缺口（B1 六数表与机会成本 / B2 变异认知 / B3 诚实边界） · `C` 回测闭环 · `D` skill 本体。

每条需求的字段：

| 字段 | 回答的问题 |
|---|---|
| 现状 | 现在是什么样，有什么证据 |
| 为什么做 | 不做会发生什么，为什么是现在 |
| 价值 | 做完后投资者得到什么、系统得到什么、迭代得到什么 |
| 交付物 | 做出什么 |
| 验收 | 怎么算完 |
| 涉及文件 / 依赖 / 状态 | 跟进用 |

价值判断的统一尺度：这个 skill 的最终目标是帮投资者做出"不错买"的决策。因此每条需求的价值都用三个问题度量：它能否阻止一次错买（最高价值）；它能否让一次本该买的机会被识别（次高）；它能否让系统知道自己错在哪（长期价值）。工程债只服务于前三者的可持续性。

执行波次见第 7 节。

## 1. 三大原则的补齐说明（本清单的设计依据）

### 1.1 数据真实性与全链路可溯源

为什么这是地基：任何估值方法在错误数据上都是精确的错误。投资分析里最贵的错误不是"估值差了 10%"，而是"这家公司的利润是假的"。康美（600518）和柯达（EK）已在案例库里，说明作者认同这一点；但当前的实现里，数据真实性主要靠人的纪律（官方源优先、转录核对）与两个脚本（`crosscheck_official.py`、`verification_strength.py`），人的纪律在第二批回测里已被证明不可靠（隔离协议 6 例只执行 1 例）。

仍缺的维度（对应 REQ-P0-02/03/06/07、REQ-P3-05/06）：

- 时点正确性（point-in-time）：回测底稿必须是截断日当时可得的数据，不能用后来重述的数字。这是回测里最隐蔽的作弊方式，因为重述值通常更"干净"，会让回测结果系统性偏乐观。
- 源冲突裁决规则：两源不一致时谁优先、差异多大必须登记、是否阻断，目前只有口头纪律。没有规则，差异就会被"就近取一个"吞掉，而差异本身往往是财务异常的第一信号。
- 非财务数据溯源：市场份额、行业基率、管理层原话这类来自搜索的内容，需要引用 URL、检索日期与失效降级路径。护城河判断有一半证据来自这里，但目前这部分完全不可复核。
- 稀释与股本口径：RSU、可转债、回购注销对每股 OE 的影响是静默误差源。对高 SBC 公司，忽略稀释会让每股价值高估 10%～20%，正好吃掉安全边际。
- 表外与关联方：VIE、担保、关联交易无法从三表推导，需要附注抽取清单。A 股财务造假的主要通道就在这里。
- 覆盖度分母：报告的"信息覆盖度 <70%"声明缺少统一分母定义，导致这个数字不可比、不可验证。

### 1.2 不错买优先于不错过

为什么这是原则而不是偏好：价值投资的复利数学是不对称的。一次 50% 的亏损需要 100% 的收益才能回本；而错过一个机会的成本是有界的（最多是那一笔的机会成本）。当前 skill 把这个不对称性写进了多层（排雷一票否决、峰值利润不作基期、悲观情景独立构造、核心买入下行约束、假阳性红灯不可抵扣），这是它最正确的设计决策。但"保守"必须是有证据的保守，而不是双闸门重复计价造成的意外保守；后者不是审慎，是噪声，它让系统在该出手时不出手，同时并不能更好地拦住该拦的。

仍缺的维度（对应 REQ-P0-04/05、REQ-P1-04/05、REQ-P2-06、REQ-P3-01/06）：

- 保守要有证据：双闸门同源重复计价必须修。名义 25% 的门槛实际是 40%，这 15 个点不是任何人决定的，是公式结构的副产品。
- 尾部风险单列：欺诈、监管、治理突发不应混入悲观情景的增速折扣。把"利润增速 -5%"和"公司可能归零"放进同一个情景，既低估了尾部，又让正常悲观情景失去意义。
- 不对称性要可度量：回测应报告假阳性率与假阴性率的实际比值，并设目标区间（如 FP ≤10%、FN ≤40%）。不度量的原则只是口号，度量之后才能知道系统是"审慎"还是"胆小"。
- 基率锚定：乐观情景增速上限不应超过行业历史基率的高分位。没有基率，乐观情景就是分析师想象力的上限，而不是现实的上限。
- 仓位约束：核心买入档位需配套最大单仓比例。下行约束在单笔层面成立，在组合层面同样成立，否则"核心买入"会被解读为"全仓"。
- 论点失效时限：允许论点"暂时错"多久，超时即触发退出。没有时限的论点是不可证伪的，而不可证伪的论点会让投资者无限期持有错误。
- "太难"是正式输出：不是失败，应有专门档位与统计。芒格的"太难"篓子是价值投资体系的一部分，系统需要有勇气说"我不知道"。

### 1.3 可证伪与反馈闭环

为什么这决定了系统的寿命：一个不能知道自己错在哪的分析系统，无论今天多准，都会随市场结构变化而退化，而且退化时没人会发现。当前 skill 把"我可能错"作为一等公民设计进去了（五字段关键变量、决策日志双写、6/12 个月复盘、回测三轨、observations 单一事实源），这是它最难得的地方。但目前的闭环有三个断点：回测只有正向样本、规则改动后旧战绩不可复现、闭环协议（隔离、预注册、复盘）靠自觉执行。三个断点任何一个存在，闭环就是开环。

仍缺的维度（对应 REQ-P0-01/05/08、REQ-P1-06、REQ-P2-01～09）：

- 规则版本钉死：每个 verdict 必须记录当时 skill 的规则版本。否则改了规则之后，无法区分"系统变好了"和"规则变松了"，所有历史战绩都失去参照。
- 校准而非命中：概率输出应用 Brier 分数评估，情景区间应统计实际覆盖率。档位命中只回答"对不对"，校准回答"该有多自信"，后者才是投资者仓位决策需要的。
- 分市场与分体制切片：A 股、港股、美股与不同利率周期下的结果分开统计。混在一起的平均数会掩盖"系统在 A 股周期股上系统性失效"这类关键发现。
- 规则变更日志：每条规则改动必须登记动因案例、预期效果与事后验证结果。没有日志，规则就会变成"因为某个案例临时加的补丁"的堆积。
- 弃权率追踪：观察/太难的占比是系统健康度指标，过高说明框架覆盖不足，过低说明过度自信。
- 预注册：关键变量与阈值在看到结果前锁定，锁定方式需机器可验证。事后调参数是回测里最常见也最难察觉的自欺。

### REQ-P0-01 假阳性专项前置
- 来源：A3、C
- 现状：两批共 12 个回测案例全部是"事后表现好"的正向样本；`observations.md` 得出"系统性保守"的结论，但这个结论只有一侧证据。原路线图将假阳性基线排在第四批。
- 为什么做：一个只在正向样本上测试的选股系统，得出的"保守"结论毫无意义，因为它可能同时也放行了一堆事后爆雷的公司，只是没人拿这些公司去测。更严重的是，W3 波次要放松双闸门（REQ-P0-04），放松之前必须有假阳性对照，否则无法知道放松是否放进了坏公司。假阳性专项排到第四批，意味着前面所有框架修正都是在没有刹车的情况下调油门。

### REQ-P0-02 排雷算术条款落码 `forensic_screen.py`
- 来源：A1、D
- 现状：Phase 0 排雷清单 30 项，全部人工核对。康美案例的"存贷双高"是人工登记后才命中，脚本层面没有任何一条算术条款。
- 为什么做：排雷是"不错买"的第一道也是最重要的一道防线，而它现在完全依赖执行者的耐心与警觉。人工核对 30 项在真实使用中必然被跳过或敷衍，回测里能命中是因为执行者知道这是回测。可算术的条款（存贷双高、利率倒挂、现金流利润背离、应收存货剪刀差）有清晰的数学定义，留给人做只会增加漏检。此外，尾部风险单列（REQ-P1-05）需要一个排雷得分作为 `p_tail` 的输入，没有落码的排雷就没有可用的得分。
- 价值：直接阻止错买。这是全清单里"阻止一次灾难性亏损"概率最高的一条。康美、康得新、乐视类公司在这些条款上有明确的算术信号，机器化后不再依赖任何人是否"想起来查"。对系统而言，排雷得分成为后续尾部概率、情景概率的可量化输入。
- 交付物：新建 `scripts/forensic_screen.py`，实现至少以下条款并输出 P0_* 告警码：存贷双高（货币资金/总资产 与 有息负债/总资产 同时高位）、利息收入/货币资金 低于同期存款利率（利率倒挂）、经营现金流/净利润 连续 N 年 <0.8、商誉/净资产 阈值、累计融资/累计分红回购 比值、应收增速 与 收入增速 剪刀差、存货增速 与 收入增速 剪刀差、其他应收/总资产、审计意见非标、审计师更换频率。输出结构化排雷得分供下游使用。

### REQ-P0-03 底稿 schema 强类型化
- 来源：A1、D
- 现状：底稿数值字段靠 `_frac/_pct` 命名后缀约定单位；单位、币种、复权、报表口径没有字段承载。OBS-600660-01、S9b、OBS-000895-02 三条观察全部是量纲错误。
- 为什么做：量纲错误是"精确的错误"的典型形态：所有公式都对，结论差一个数量级。命名约定无法拦截，因为它依赖写入者记得约定；三条已登记观察说明这种错误在有经验的执行者手里也反复发生。更根本的是，后续几乎所有 P0 需求（排雷落码、时点校验、源裁决、A 股港股官方源）都需要字段级元数据作为输入，schema 不定，这些需求就没有落地的载体。
- 价值：这是全清单里杠杆最大的一条基础设施。它不直接产生投资结论，但它让后续每一个脚本都能拒绝错误输入而不是静默传播错误。对投资者而言，报告里的每个数字都可以回溯到"哪个文件第几页、什么单位、什么口径、何时可得"，这是"可溯源"从口号变成事实的前提。

## 3. P1 框架级

### REQ-P1-01 成长股 / 再投入型估值通道
- 来源：A、D
- 现状：估值以当期 Owner Earnings 为基期做反向 DCF。对高再投入公司（Netflix 2012、亚马逊 2010 类），当期 OE 被增长性资本开支压低甚至为负，Netflix 案例缺口 2 档。
- 为什么做：六卡公司类型里成长股是投资者最常问、也是错买与错过成本都最高的一类。用 OE 框架估成长股不是"保守"，是用错了尺子：它把"为未来投入"和"赚不到钱"混为一谈。系统若对这类公司一律输出"观察"，等于放弃了约三分之一的可分析标的，同时也无法拦截真正的成长陷阱（收入增长但单位经济恶化的公司），因为它根本没有看单位经济。
- 价值：让系统对成长股既能说"买"也能说"不买"，并且两者都有依据。单位经济（LTV/CAC、边际贡献率）是区分"再投入"和"烧钱"的唯一可量化标准，这一维度加进来后，Netflix 和乐视在框架内会得到相反的结论，而不是同样的"观察"。
- 交付物：`growth-framework.md` 补齐单位经济（LTV/CAC、边际贡献率）、渗透率天花板、成熟期利润率反推三段式；`reverse_dcf.py` 新增 `--mode growth`，以成熟期稳态利润 × 到达概率 折回替代当期 OE。到达概率与基率表（REQ-P1-05）挂钩。
- 验收：Netflix 案例缺口 ≤1 档；至少 2 个新成长股案例作锚（正向与假阳性各一）。
- 涉及文件：`references/company-types.md` 卡四、`references/growth-framework.md`、`references/valuation-guide.md`、`scripts/reverse_dcf.py`

### REQ-P1-03 护城河评级连续化
- 来源：A2、D
- 现状：护城河评级为离散词（宽/窄/无），通过 `MOAT_MOS_REQUIREMENT` 阶跃映射为 MoS 门槛。神华案例"宽"与"窄"一字之差跨两档。

### REQ-P1-04 折现率与情景概率的证据传导
- 来源：A2、D
- 现状：折现率统一 10%，三情景概率固定（如 25/50/25）。这两个参数对 IRR 与期望值的敏感度最高，证据最弱。
- 为什么做：期望 IRR 的公式是 Σ p_i × IRR_i，概率固定意味着无论护城河多宽、变异认知多强、红队反驳多有力，期望值的权重都一样。这使前面所有定性分析（Phase 3 护城河、Phase 4.5 变异认知、红队）对最终数字没有影响，只影响文字。折现率统一 10% 则把 A 股周期股和美股消费龙头放在同一风险水平上，这显然不对。
- 价值：让定性分析真正进入数字。做完后护城河得分、变异认知强度、红队悲观概率都会改变期望 IRR，投资者能看到"因为 X 证据，悲观概率从 25% 上调到 35%，期望 IRR 从 12% 降到 9%"这样的传导链。这是"专业、科学、系统"三个词里"系统"的实质含义。
- 交付物：折现率按行业与国别风险分层表（引用来源）；情景概率与护城河得分、Phase 4.5 变异认知强度、红队悲观概率挂钩，给出映射公式与可调范围；`check_scenarios.py` S7 校验概率来源字段非空。
- 验收：每个案例的折现率与概率在 `verdict.json` 中有 `rationale_ref`；敏感性表显示概率 ±10pp 对档位的影响。
- 涉及文件：`references/valuation-guide.md`、`scripts/reverse_dcf.py`、`scripts/check_scenarios.py`

- 状态：todo

### REQ-P1-05 尾部风险单列与基率锚定
- 来源：A2
- 现状：欺诈、监管、治理突发等尾部风险被混入悲观情景（表现为更低的增速假设）；乐观情景增速没有行业基率上限。
- 为什么做：把"利润增速 -5%"和"公司归零"放进同一个悲观情景，两者都被扭曲：悲观情景的增速被压得不合理地低（因为要"体现"尾部），而真正的归零风险又只体现为增速折扣（远远低估）。期望 IRR 的正确公式应该是 (1 - p_tail) × Σ p_i × IRR_i + p_tail × loss_tail。基率锚定则是乐观情景的天花板：没有它，乐观情景的增速上限就是分析师的想象力，历史上"20 年 20% 增速"的公司不到 1%，但分析师的乐观情景里出现频率远高于此。
- 价值：期望值更真实，尤其对治理有疑点的公司。做完后一家排雷得分差的公司，即使三情景 IRR 都不错，期望 IRR 也会被 p_tail 显著拉低，这正是"不错买"应有的数学形态。基率表同时服务于双闸门换源（REQ-P0-04）与成长股通道（REQ-P1-01）。
- 交付物：期望 IRR 公式新增 `p_tail × loss_tail` 独立项，`p_tail` 由排雷得分（REQ-P0-02 输出）与治理评分映射；建立行业增速基率表（`references/base-rates.md`），乐观情景增速不得超过基率 80 分位，超出需 Phase 4.5 显式变异认知支撑。
- 验收：基率表覆盖回测案例涉及的全部行业；违反基率上限的情景被 `check_scenarios.py` 拦截。
- 涉及文件：`references/valuation-guide.md`、`references/base-rates.md`（新）、`scripts/reverse_dcf.py`、`scripts/check_scenarios.py`
- 依赖：REQ-P0-02
- 状态：todo

### REQ-P2-06 校准指标与分市场切片

- 现状：美股有 EDGAR XBRL 机器抽取，核对等级 A；A 股、港股命门科目靠人眼从 PDF 转录，核对等级低。附注（表外担保、关联交易、VIE）没有抽取清单。
- 为什么做：A 股是财务造假高发市场，恰恰也是当前核对等级最低的市场，这个错配本身就是风险。人眼转录 PDF 的错误率不低，且不可复核。附注是 A 股造假的主要藏身处（关联方占款、对外担保、体外循环），三表看不出来，必须从附注抽取。非财务数据（市场份额、行业基率）目前完全依赖搜索且不留引用，护城河判断的一半证据不可复核。
- 价值：让 A 股、港股的数据可信度追平美股。对主要投资 A 股的用户，这是"数据真实性"原则从美股特权变成普遍保障的关键一步。
- 交付物：新建 `scripts/extract_cninfo_annual.py`（巨潮 XBRL）与港交所披露易抽取；`crosscheck_official.py` 支持三市场命门科目机器比对；附注抽取清单覆盖表外担保、关联交易、VIE 结构；非财务数据引用带 URL 与检索日期。
- 验收：A 股案例核对等级达到与 EDGAR 同等的 A 级；非财务数据引用带 URL 与检索日期。
- 涉及文件：`references/data-sourcing.md`、`scripts/extract_cninfo_annual.py`（新）、`scripts/crosscheck_official.py`

### REQ-P3-06 稀释、股本口径与仓位约束
- 来源：A1、A2
- 现状：每股 OE 用当前流通股本计算，RSU、可转债、回购注销的影响未入底稿；档位规则表只给"买/观察/不买"，没有仓位上限。
- 为什么做：对高 SBC 公司（多数美股科技股），忽略稀释会让每股价值高估 10%～20%，正好是一个安全边际的量级，这意味着系统以为的 25% MoS 实际可能只有 5%。这是静默误差：所有公式都对，只是分母用错了。仓位约束则是"不错买"在组合层的延伸：单笔下行约束再严，若允许全仓，一次尾部事件仍能毁掉组合。
- 价值：安全边际是真的安全边际；核心买入不会被解读为全仓。
- 交付物：底稿新增 `diluted_shares`、`sbc`、`convertibles` 字段并进入 `compute_metrics.py`；档位规则表新增最大单仓比例（如核心买入 ≤15%、观察 0%）。
- 验收：Netflix、Zoom 等高 SBC 案例每股 OE 变化在报告中显示；报告输出建议仓位上限。
- 涉及文件：`scripts/compute_metrics.py`、`references/valuation-guide.md`、`references/report-spec.md`
- 依赖：REQ-P0-03
- 状态：**doing**（2026-09-11 算术条款落码完成，待底稿补字段提升覆盖率）

## 7. 执行波次

排序原则：先做不涉及方法论争议、且能立即提升后续所有回测可信度的地基（W1）；再建立假阳性对照与排雷防线（W2）；有了对照才能安全地修正框架（W3）；最后扩展覆盖面（W4）。P2、P3 大部分不阻塞主线，可并行。

| 波次 | 需求 | 目标 | 前置 | 为什么这个顺序 |
|---|---|---|---|---|
| W1 | P0-03、P0-05、P0-08、P0-06 | 地基：schema、隔离、版本、时点 | 无 | 四条都是"让后面的数据可信"，不做它们，W2 起的所有回测结果都带不可量化的污染 |
| W2 | P0-01、P0-02、P0-07、P2-09 | 假阳性基线 + 排雷落码 + 源裁决 + 预注册 | W1 | 假阳性对照是 W3 放松闸门的前提；排雷落码是尾部单列的输入 |
| W3 | P0-04、P1-03、P1-04、P1-05 | 框架修正：闸门、护城河连续化、概率传导、尾部与基率 | W2 | 这四条互相耦合（闸门二用基率表，概率传导用护城河得分），必须联合设计；有了假阳性对照才能证明修正没放松防线 |
| W4 | P1-01、P1-02、P1-07、P1-06 | 覆盖面扩展与无标签滚动回测 | W3 | 新通道需要 W3 修正后的框架作为基础；滚动回测需要 W1 的时点与版本 |
| W5（并行） | P2-01～P2-08、P3-01～P3-06 | 闭环指标与价值交付 | 各自依赖 | 大多不阻塞主线；P3-02/03/04 无依赖可最早开始 |
| W6 | P4-01～P4-04 | 工程债 | 随时 | P4-02 应紧随 P0-03；其余随时 |

建议最早启动的无依赖项：P0-03、P0-05、P0-08、P3-02、P3-03、P3-04、P2-04、P2-05。其中 P3-03（变异认知硬化）和 P3-04（诚实边界模板化）实施成本极低而对报告质量影响直接，可在 W1 期间顺手完成。
