# value-investing-analyst

对单一公司做机构级价值投资深度分析，输出一份数字与图表全程可溯源校验的中文单文件 HTML 报告。

本仓库同时是**价值分析管理仓库**：`cases/` 存档全部真实分析案例（数据底稿+工作底稿+决策日志+报告），供历史回溯、触发价跟踪与复盘校准；案例暴露的问题持续固化为引擎修复，git 历史即方法论进化史。案例索引与跟踪清单见 [cases/README.md](cases/README.md)。

流水线：排雷过滤 → 数据采集（双源核对 + 入口校验）→ 定量画像（统一口径 + 周期正常化 + capex 拆分）→ 五维定性（商业模式/护城河/增长/管理层/财务质量）→ 估值与安全边际（基期正常化 + 三情景 DCF + 反向 DCF + 基率检验 + 假设一致性对账 + 期望回报率）→ 关键判断收敛（关键变量/变异认知/机会成本）→ 三位大师独立评估（巴菲特/段永平/李录，各自从原始证据独立推导，显式呈现分歧）+ 芒格式红队 → 四档结论（核心买入/观察等价格/太难放弃/排除）+ 证伪条件 + 跟踪清单 + 决策日志 + 复盘校准。

## 核心设计

- **数据五环校验**：官方源/结构化接口 → `validate_data.py` 入口校验（三表勾稽/单位突变/双源核对/发布日）→ 数据底稿（唯一事实源）→ `compute_metrics.py` 统一口径计算 → `verify_report.py` 报告溯源校验（vnum 数字 + vchart 图表 + [E:] 证据指针三层）。
- **基期正常化关卡**：周期高位公司（最新净利率 > 全期均值 1.25 倍）禁止用当期 Owner Earnings 作 DCF 基期，脚本自动判定并给出正常化基期区间；周期低位反向向上正常化。峰值利润外推是周期股估值最经典、最自信的翻车方式——NVDA 样例中仅此一项就把结论从"贵一点点"修正为"高估 65%"。
- **双闸门定档位**：安全边际回答"贵不贵"，期望年化 IRR 回答"划不划算"，下行指标（悲观情景 IRR/亏损概率/亏损跌幅）回答"错了会怎样"，共同决定四档结论。大师评估与红队只校准置信度、呈现分歧，不改变档位——好公司 ≠ 好价格。**注意闸门二的期望值部分是闸门一的单调函数**（买在内在价值上时 IRR 恒等于折现率），增量约束来自门槛设定（须高于折现率）、情景概率与下行指标，报告不得把两闸门当成两份独立证据。
- **估值可靠性诊断**：`forward-value` 自动输出终值占比（永续终值现值 ÷ 总值）。占比 ≥75% 时估值主体来自看不见的远期，禁止以"安全边际达标"单独支撑买入——永续增速 ±1pct 带来 ±15~20% 的价值波动，已超过"安全边际 25% vs 40%"的分辨率，此时精确的安全边际数字是虚假精确。
- **三位大师独立评估**：不是换视角打分。三份评估分离生成、互不参考、不合成单一分数，分歧对照表是核心产出；红队必须独立出数（自己的悲观情景价值 + 自己的情景概率）。
- **行业类型门控**：金融股禁走通用管道（脚本硬拒绝），银行有专属管道（NPL/拨备/PB-ROE）；大宗商品用中周期价格正常化；pre-revenue 直接判超出能力圈。
- **反馈闭环**：决策日志双写（人读 md + 机器读 json），6/12 个月复盘校准协议对照关键变量判断与实际走向，≥5 次复盘归纳系统性偏差反哺 skill。

## 使用

把本目录作为智能体 skill 加载，直接说"分析一下 XX 公司（股票代码）"。流程细节见 `SKILL.md`（30 秒纪律卡在最顶部），方法框架见 `references/`。

## 黄金样例

`cases/nvidia/` 是一次真实全流程分析，特意保留了初版估值错误（峰值基期）与修订结果（正常化基期）的对照——亏损概率 30% → 80%，是"基期正常化"关卡价值的实证。样例的投委会章节为 v1 评分卡结构，新框架下会呈现为三份独立评估 + 分歧对照表（见样例 README 的框架演进说明）。

## 实证状态

- 已实证（全流程真实标的）：美股（英伟达 + 三竞对、台积电、谷歌）、中概美股（拼多多、微博）、A股（伊利股份）、A股银行专属管道（招商银行 + 四大行对照）、A股保险专属管道（中国平安）、港股（泡泡玛特、腾讯控股）。脚本引擎全部经回归测试覆盖（65+ 项）。
- 未实证：券商（无专属管道，触达时须手工建稿并按实证模式操作）、周期低位真实标的（向上正常化逻辑仅合成数据测试过）、方法树新增四类（公用事业 DDM+RAB、重资产扩张期、零售连锁单店模型、医药 rNPV）尚无真实案例。首次触达时踩坑固化回 `references/data-sourcing.md`。

## ⚠️ v2.9 期望回报口径修正（影响已归档案例结论）

2026-08-31 发现并修复一个**结构性错误**：`expected_return` 此前用 `IRR=(V0/P)^(1/H)−1`，隐含假设"内在价值 H 年原地不动、期间赚的现金凭空消失"。正确口径是内在价值按折现率增值：

```
IRR = (1+r)×(V0/P)^(1/H) − 1     （已隐含分红 + 留存增值，股息不得再叠加）
```

影响：旧口径对留存再投资的公司系统性低估 IRR 3~10 个百分点。**重算 10 个归档案例，其中 4 个（招商银行 7.63%→12.77%、拼多多 4.53%→14.98%、腾讯 3.75%→12.84%、中国平安 6.84%→12.24%）闸门二结论从"不通过"翻转为"通过"**，即旧引擎系统性误杀了这批机会。诊断信号：若一批案例的 IRR 集中落在 0~8% 这个"就差一点"的区间，先怀疑口径而非市场。

同时暴露一个设计问题：默认配置（折现率 10% / 门槛 9%）下门槛低于折现率，**闸门二本就形同虚设**（买在内在价值上即自动过闸）。现要求门槛取 `max(指数长期年化, 折现率+3pct)`，引擎在门槛 ≤ 折现率时打印警告。风险差异不应通过提高折现率表达（r 越高 V0 越低但 IRR 起点也越高，两个方向相反，会让高风险标的反而更容易过闸），应体现在安全边际要求与情景概率上。

**归档案例的 `expected_return.json` 与 HTML 报告为当时口径原样保留**（存档不追溯改写，保持决策日志的历史真实性）；重跑任何案例时按新口径执行，并在决策日志注明口径变更。

## 边界

不做买卖时点与仓位建议，只输出企业价值判断与安全边际结论；报告含免责声明，不构成投资建议。
