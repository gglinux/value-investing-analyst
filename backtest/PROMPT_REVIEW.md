# PROMPT.md 审查与第二批可用改进方案

> 审查对象：`backtest/PROMPT.md`（第一批已按其执行完毕）
> 审查日期：2026-09-05
> 目的：让第二批（神华/鞍钢/Netflix/软银/Zoom/双汇）在同一份提示词下产出**可机器复核**的结果，并把第一批暴露的协议缺陷补掉。
> 用法：第一节列问题与修法；第五节给**可直接替换/追加的补丁文本**，改完即可投喂执行第二批。

## 0. 总评

`PROMPT.md` 的**案例设计是这份文件最强的部分**——六类判别力覆盖、选型说明（为何用柯达不用诺基亚、为何海控是最锋利的一个）、成对执行要求（神华 vs 鞍钢）、假阴性专项（Meta/伊利），这些体现了真实的投资判断，不需要改。

问题集中在**协议工程**：它把"该测什么"写得很好，把"怎么保证测出来的东西可信、可复核、可回归"写得不够。第一批 6 案例的执行缺陷（见 `SKILL_IMPROVEMENT_REPORT.md` 第一节）里，**至少 5 项的根因在提示词本身**，而不是执行者偷懒。

按严重度排序的 12 项问题，其中 P1-P5 建议在第二批前必改。

## 一、必改项（P1-P5）

### P1｜答案与任务书写在同一个文件里 —— 结构性污染的真正源头

**现状**：第七节"事后答案"用 `<details>` 折叠在 `PROMPT.md` 内部，紧跟在案例表之后。而第三节的复用方式写的是"把本文件**全文**投喂给 AI"。

**后果**：执行者要读案例清单，就必然读到答案。第一批 **6/6 案例**的 `contamination_disclosure` 都写着"执行上下文已暴露于 PROMPT.md 第七节事后答案文本（本 session 早前全文读取过）"。第一节把这件事定性为"你已经知道答案，这是无法回避的污染源"——**但它可以回避，只要把答案挪出去。**

第一批的 R5 裁决（"第二批起由未读答案的独立上下文执行"）方向对，但**光靠执行纪律不够**：只要答案还在同一个文件里，任何一次"完整读一遍任务书"就重新污染。

**修法**：
1. 第七节整体移出到 `backtest/ANSWERS.md`，`PROMPT.md` 只留一句指针："事后答案在 `backtest/ANSWERS.md`，**Step 4 之前禁止打开**"。
2. 第三节复用方式改为："投喂 `PROMPT.md`（不含答案）；执行 Step 4 时才允许读取 `ANSWERS.md` 的对应案例段"。
3. `ANSWERS.md` 按案例分段，并要求 Step 4 只读当前案例段（避免读一个案例污染整批）。
4. 更彻底的做法（推荐）：答案直接落成每案例的 `answer.json`，由第三方（用户）在 Step 3 完成后再放入案例目录。这样执行上下文**从物理上拿不到**答案。

> 这是全部 12 项里收益最大的一条：它把"污染不可避免"变成"污染可避免"，也是唯一能让"制造一次真正的失败"这个目标真正可信的前提。

### P2｜第九节 meta.json 格式与 Step 1 自相矛盾，直接导致断言库为空

**现状**：
- 第六节 Step 1："在跑分析**之前**创建 `meta.json`，登记回放时点、信息截断日，以及你在跑分析之前的先验预期档位。**写入后不得修改**。"
- 第九节给的 `meta.json` 格式却包含：`expected_verdict`（官方预期）、`actual_3y_total_return`、`actual_5y_total_return`、`actual_max_drawdown`、`outcome_note` —— **全部是答案**。

**矛盾**：照字面执行，必须在跑分析前把答案写进 meta.json，这与第一节"先完整跑完分析并落盘，再看答案"直接冲突。执行者只能二选一，第一批的实际选择是：用自建的 `prior_expectation` 装自己的先验，把答案字段**全部留空**。

**实测后果**：6 个案例的 `actual_3y_total_return` / `actual_5y_total_return` / `actual_max_drawdown` / `outcome_note` **全部为 `null` 或字段不存在**；福耀/海控更是整体换了 schema，缺 9 个必需字段。于是第九节承诺的"把该不该报警变成可自动判定的断言"**在第一批完全没有兑现**——`REPORT.md` 的战绩表是人工解读出来的。

**修法**：拆成两个文件，各自有明确的创建时点。

- `meta.json`（Step 1，跑前冻结，**不含任何答案**）：
  `ticker` / `company` / `replay_date` / `information_cutoff` / `batch` / `case_id` / `purpose` / `prior_expectation{verdict, gate1, gate2, reasoning}` / `contamination_disclosure` / `information_set` / `frozen_at`
- `answer.json`（Step 4 才创建或解封，**全部是答案**）：
  `expected_verdict_set[]` / `expected_gate1` / `expected_gate2` / `must_trigger[]` / `must_not_trigger[]` / `actual_3y_total_return` / `actual_5y_total_return` / `actual_max_drawdown` / `earnings_driven_return` / `multiple_driven_return` / `outcome_note` / `answer_source`

配套：第九节补一句"两个文件的 schema 由 `scripts/check_backtest_case.py` 门禁校验，字段缺失即 FAIL"。

### P3｜"一键重跑全部断言"是一句无法兑现的承诺

**现状**：第九节结尾："每次改引擎都应能**一键重跑全部断言**，立刻知道有没有把修好的东西弄坏。"

**实测**：
- `scripts/` 下**没有任何回放断言 runner**。
- 更根本的是：引擎告警是自由文本（`check_scenarios.py:608` 的 `print(f"  [WARN] {w}")`），**没有稳定 ID**，断言在架构上无法机器匹配。
- 断言 ID 在第一批出现 **5 种命名风格**：`S8_value_trap` / `cash_interest_contradiction` / `not_converging_floor_low` / `gate1_wide_moat_25pct` / 中文"周期高位"。没有注册表，同一个概念在不同案例里写法不同。

**后果**：`REPORT.md` 给 R1 定的验收标准"四案 verdict 与 must 断言不变"**无法执行**。而 R1 改的是情景概率与闸门阈值——系统里最危险的参数。

**修法**（提示词侧）：第九节增加"断言 ID 必须取自 `references/alert-registry.md` 注册表，自由文本断言不被接受"，并把"提供 `scripts/run_backtest_assertions.py`"列为**第二批的前置交付物**（第三节前置条件）。引擎侧的实现方案见 `SKILL_IMPROVEMENT_REPORT.md` 的 P0-1/P0-2。

### P4｜Step 3 → Step 4 的时序无任何防篡改要求

**现状**：Step 3 只说"此步完成后才允许进入 Step 4"，没说怎么证明。

**实测**：仅 **3/6** 案例的 `verdict.json` 含 `frozen_before_diff` 自陈字段（茅台/苹果/柯达），康美/福耀/海控无任何时序痕迹；文件 mtime 已被 git 检出覆盖（全部显示同一时间）；6 案例由同一个 commit 一次性提交，git 历史也无法还原先后。

**修法**：Step 3 增加硬要求（三选一，按可执行性排序）：
1. **git 存证（推荐）**：`verdict.json` 落盘后**单独 commit**（`git add <case>/verdict.json && git commit -m "verdict(<case>): 结论落盘，未读答案"`），Step 4 的 `diff.md` 必须在**后续 commit** 中提交。git 历史即时序证据，零额外工具。
2. **哈希存证**：落盘后计算 `sha256(verdict.json)` 写入 `backtest/verdict_hashes.log`（追加写），Step 4 后校验哈希未变。
3. 最低要求：`verdict.json` 强制含 `frozen_before_diff: true` + `frozen_at`（时间戳），至少统一自陈格式。

### P5｜档位没有序数化，导致"命中"与"错误拒绝"可以双计

**现状**：答案里的期望档位是自然语言区间（"核心买入 / 小仓位试探"、"拒绝 或 观察等价格"、福耀"不应排雷，应正常进入估值（不约束档位）"），Step 4 只说"档位是否匹配 `expected_verdict`"，没定义匹配规则。

**实测后果**：福耀案在 `REPORT.md` 里**同时被计入"命中"和"错误拒绝"**两个互斥的桶（总览表记 `✅ 排雷侧完全命中`，元问题 2 记 `错误拒绝`）。头条战绩"5 命中 + 1 纪律性错过"与元问题 2 的"错误/正确 = 2/3"来自同一批案例的两套口径。报告披露了这个拆分，但头条客观上淡化了保守度成本。

**修法**：
1. 档位序数化：`排除=0 / 拒绝=1 / 观察等价格=2 / 小仓位试探=3 / 核心买入=4`。
2. 答案改用集合：`expected_verdict_set: [3, 4]`（茅台）、`[1, 2]`（海控）、`[0]`（康美）。匹配判定 = `actual ∈ set`，机器可判。
3. **两条独立计分轨**（关键）：
   - **排雷轨**：`must_trigger` / `must_not_trigger` 的命中与误触发 —— 独立计分
   - **档位轨**：档位是否落入 `expected_verdict_set` —— 独立计分
   一个案例可以"排雷轨命中 + 档位轨错过"（福耀正是如此），但**两轨的分不得互相抵扣，也不得合并成一个"命中"**。
4. 官方不约束档位的案例（福耀），`expected_verdict_set` 记 `null`，档位轨记"不计分"，但**错过成本仍进入元问题 1 的统计**（只是不算"档位判错"）。

## 二、建议改项（P6-P9）

### P6｜元问题缺"假阳性"，且第一批的案例结构无法暴露假阳性

**现状**：第八节三个元问题只覆盖假阴性（元问题 1）、正确/错误拒绝比（元问题 2）、有没有制造失败（元问题 3）。**没有一问要求统计"该拒没拒"（假阳性）。**

**为什么现在必须加**：`REPORT.md` 宣称"**反向错误 0**（无漏排雷、无错误排雷、无买入踩雷、无周期顶误判）"。但第一批 6 案例里 4 个是明确的"该拒/该排雷"（柯达衰退末期、康美存贷双高、海控周期顶、加福耀负样本），**没有任何"看起来该买、实际该拒"的样本**——假阳性在结构上不可能暴露。所以"0 反向错误"更准确的表述是"本批未设置能暴露假阳性的样本"。

而 R1（放松价格闸门）实施后，假阳性风险会显著上升。第二批的鞍钢（无成本护城河、盈利在盈亏线震荡）与 Zoom（增速放缓估值仍高）**正是假阳性的检验点**。

**修法**：第八节增加元问题 4：

> **4. 假阳性成本**：统计"官方期望拒绝/观察，系统给出小仓位试探或核心买入"的案例数。若 ≥1，必须定位是哪一道闸门被放行、放行依据的证据强度是否真的达标。R1 类放松性改动实施后，本项计数**必须为 0**，否则放松过度须回滚。

### P7｜元问题 1 的判据在小样本下失效

**现状**：判据是"若正向案例**全部**没敢给正面结论 → 系统性缺陷"。

**问题**：第一批正向案例只有 2 个（茅台、苹果）。这个判据要 2/2 全错才触发，等于**几乎不可能触发**。实际结果 1/2 假阴性（50%），是相当严重的假阴性率，但按字面判据"未触发"，于是 `REPORT.md` 只能写"未触发最强判据"再自行补充论证。

**修法**：
1. 判据改为比例式："正向案例假阴性率 ≥1/3 即视为保守度超标，须给出具体阈值放松方案"。
2. 每批**保证 ≥3 个正向案例**。第二批目前正向案例为神华、Netflix（2 个，双汇是"观察等价格"、软银"观察（可接受拒绝）"、Zoom/鞍钢是拒绝）——**建议从第三批把伊利 2013-12 提前到第二批**，凑够 3 个正向，同时它本身就是 PROMPT 明示的假阴性专项。

### P8｜错过成本没有归因口径（盈利驱动 vs 倍数扩张）

**现状**：答案只给 `actual_5y_total_return` 这类总回报，Step 4 与元问题 1/2 直接用总回报衡量错过成本。

**问题**：福耀错过的 +185.6%，主体是 PE 13.3→52 的倍数扩张（2020 全球零利率 + A 股龙头抱团），不是盈利兑现（2019 年归母实际 −29.7%）。`REPORT.md` 第六节第 5 点自问"倍数扩张不可预期，错过成本是否应全额计给系统"，但**没有裁决**——而这个口径直接决定元问题 2 的分子。

**修法**：`answer.json` 的回报字段拆两项：`earnings_driven_return`（EPS 变化贡献）与 `multiple_driven_return`（PE 变化贡献），用期初期末 EPS/PE 做归因分解。元问题 2 的"错误拒绝"**只计盈利驱动部分**，倍数扩张单列为"未捕获的情绪溢价"，不计入系统错误。既不放过真错过，也不把流动性红利算成系统缺陷。

### P9｜"落到具体文件与具体行"这条要求本身会腐烂

**现状**：Step 4 要求根因"必须落到具体文件与**具体行**"。

**实测**：
- **5/6** 案例的 `diff.md` 无任何 `文件:行` 级定位。
- 唯一做到的茅台案，**其中一个引用是错的**：`diff.md:36` 写 "`SKILL.md:110`（闸门一：MoS ≥25%）"，但 `SKILL.md:110` 实际是"5.5 三情景门禁"，且 **SKILL.md 全文根本不含 25% 这个门槛**——真实定义在 `references/moat-framework.md:33`。
- 根因：SKILL.md 当前 163 行、已有 14 次提交历史，行号必然漂移。

**修法**：改为"落到具体文件与**稳定条款号**"。给 SKILL.md 每条纪律加锚点编号（`[P4-G1]` 闸门一 / `[P4-G2c]` 闸门二③ / `[P4-S5.5]` 三情景门禁），`diff.md` 引用条款号。同时明确"若根因在 `references/` 而非 `SKILL.md`，须指向真实定义处"——第一批的错误定位正是把 references 的内容归给了 SKILL.md。

## 三、可选改项（P10-P12）

### P10｜publish_date 附录无格式规范、无校验

第一节要求"结尾列出全部引用数据的 `publish_date`，晚于截断日的自行标红作废"。实测**3/6** 有结构化附录（茅台/苹果/柯达标题即"附录（全部 publish_date）"），康美/福耀/海控只在正文散记（实质合规、不可机器校验）。

**修法**：规定附录为固定结构（表格：数据项 / 来源文件 / publish_date / 是否晚于截断日），并纳入 `verify_report.py` 的回放模式校验。

### P11｜第二批前置条件存在循环依赖

第三节前置条件写的是"第一批引入的引擎改动**已过全量回归**"。但全量回归工具（断言 runner）不存在，而它本身就是第一批发现的缺口之一。照字面执行，第二批永远无法启动。

**修法**：前置条件改为分层表述：
- 硬前置：**基础设施就位**（断言注册表 + runner + schema 门禁），且 6 个存量案例断言全绿（基线建立）
- 软前置：判别逻辑改动（R1）**不作为第二批前置**——建议放在第二批之后，理由是第一批只有 2 个正向案例，n=2 上校准概率参数过拟合风险高；第二批跑完可再补 2-3 个正向样本，届时校准更稳。同时第二批在"未放松"状态下跑，还能提供 R1 的对照基线。

### P12｜未区分"文献时点"与"事实时点"

第一节说"只能使用该日期之前**已公开披露**的年报、季报、公告，以及该日收盘价"。

**边界情况**（柯达案实际发生）：执行者用 **FY2012 10-K**（2012 年申报，晚于截断日 2011-06-30）的封面市值锚点，去还原 2011-06-30 的收盘价 3.58。事实本身（当日收盘价）截断日可知、明确在允许范围内；但**载体文献**晚于截断日，且该文献同时包含大量后见之明内容。

**修法**：第一节补一条判定规则：

> **文献时点 vs 事实时点**：允许用晚于截断日的文献**回取**截断日之前的客观事实（收盘价、已披露报表数字），但必须满足：① 在 `information_set` 中标注"事实时点 X，载体文献 Y（晚于截断日）"；② 只取该文献中的**客观历史数字**，禁止使用其中的前瞻表述、管理层讨论、后续事件描述；③ 优先寻找截断日之前的原始载体，回取仅作为兜底。

## 四、不需要改的部分（明确保留）

避免过度修订，以下部分第一批验证有效，建议原样保留：

- **第二节的案例设计与选型说明**：柯达优于诺基亚的论证、海控"最锋利"的判断、福耀作为排雷负样本的必要性（"没有它，排雷模块可以靠一律怀疑刷满分"）——第一批实测证明这三条判断都对，福耀的负样本约束确实生效（排雷 0/30 误杀）。
- **第五节"≥2 案例才改代码"门槛**：第一批的适用与豁免边界（`REPORT.md` 4.3 节区分"判别逻辑"与"工程卫生")论证站得住，规则本身不用改，建议把 4.3 节的边界说明**上收进 PROMPT 第五节**，免得每批重新论证。
- **第一节的信息截断红线**：除 P12 的边界补充外，主体不动。第一批 6/6 未发现红线违反，说明这条写得足够清楚。
- **第六节 Step 1-5 的五步骤框架**：框架正确，问题在于 Step 1/3/4 缺可验证性要求（已由 P2/P4/P9 补）。
- **第四节案例 7/8 成对执行的要求**：这是第二批最有价值的设计，且明确了"若给出同一档位 = 方法论缺陷而非阈值问题"的判据。

## 五、可直接套用的补丁（第二批用）

以下为具体替换/追加文本。可全部套用，也可只套 P1-P5。

### 补丁 1：第一节末尾追加（P12）

```markdown
- **文献时点 vs 事实时点**：允许用晚于截断日的文献回取截断日之前的客观事实（收盘价、已披露报表数字），
```

**档位序数**：`排除=0 / 拒绝=1 / 观察等价格=2 / 小仓位试探=3 / 核心买入=4`。
