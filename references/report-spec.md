# 报告规范（Phase 5 输出）

## 形态

- 单文件 HTML，内嵌 ECharts（CDN 引入 + 本地降级提示），可离线阅读文字部分。基于 `assets/report_template.html` 修改生成。
- 文件名：`<公司名>_价值投资分析报告_<YYYYMMDD>.html`，存放于 `<公司名>_analysis/` 目录。
- 语言：中文。语气：专业、直接、有态度；每个章节先给结论再给论据（金字塔结构）。
- **术语白话化**：关键术语（ROIC、ROIIC、Owner Earnings、反向 DCF、NDR、安全边际等）首次出现时用括号给一句白话注释；附录提供术语速查表。目标读者是认真但非科班的个人投资者。

## 章节结构（依序）

1. **投资摘要（一页）**：**首屏决策卡置顶（一张卡片区块，用户只看它就能决策）**，七项内容：① 结论档位大字呈现；② 双闸门（闸门一：安全边际 % vs 护城河对应门槛；**闸门二三项各带 ✓/✗**——期望 IRR vs 由闸门一反推的门槛并**明示该项只是自洽性校验、与闸门一同源**、价值不收敛下限 vs 下限门槛、悲观情景年化 vs 悲观门槛并注明悲观值由哪种独立方法推导；另附亏损概率与亏损情景平均跌幅）；**②b 核验强度徽章（强制，见下）**；③ 1~3 个关键变量一句话各附当前判断；④ 证伪条件（最关键的 1~2 条）；⑤ 下次复查时间（下个财报日或触发价）；⑥ 市场快照信息卡（现价/总市值/PE-TTM/PB/股息率/52周位置/日均成交额，数据取自 `data/market_snapshot.json`，标注抓取时间）。决策卡之后依次：三人结论对照（不合成分数）+ 估值区间 vs 现价横条图 + 三大投资论点（各一句话）+ 三大风险（各一句话）+ 一句话生意描述 + **信息局限声明**（哪些结论因数据缺失或信息劣势置信度打折，普通投资者相对机构在该股上的信息差有多大）。
2. **公司与生意**：大白话讲这门生意、收入结构图、商业模式要点。
3. **定量画像**：Phase 2 全部图表 + 每图一段"这张图说明什么"。图表必须有洞察标题（如"ROIC 连续 12 年高于 WACC：护城河的定量证据"，而非"ROIC 走势图"）。含每股口径复核结果（总量增长 vs 每股增长的差异及原因）。
4. **护城河**：五源归类表、定量验证结果（含定价权三项硬测试）、宽窄评级与趋势。
5. **增长**：TAM/S 曲线/增长分解表/ROIIC 判读。
6. **管理层与文化**：资本配置雷达图、承诺 vs 兑现对照表、诚信与文化结论。
7. **财务质量与风险**：排雷结果摘要 + 深查发现 + A股标的的防割附加清单结果 + **可及性与摩擦**（购买渠道、港股通红利税、汇率敞口、交易时区等实际摩擦成本，简短一段即可）。
8. **估值**：方法选择理由、三情景区间图、反向 DCF 对照表、敏感性表、安全边际结论。
9. **关键判断（Phase 4.5）**：关键变量表（变量/当前判断/依据/为什么可知）+ 变异认知三问（市场为什么给这个价/我们的分歧/认知优势来源）+ 双重机会成本对照表（vs 指数、vs 用户最好持仓）。
10. **投委会评审**：三位大师独立评估全文（各自从原始证据独立推导、用本人语言、引具体数据）+ **分歧对照表**（3~5 个关键问题上三人的不同回答，分歧是核心产出）+ 共识点 + 本次采纳裁决及理由 + 红队逐项输出（含对每份评估盲区的质询）。禁止把三人分数加权成一个综合分——那会抹平分歧。
11. **结论与行动**：档位 + **持有体验预演**（历史最大回撤/修复时长/"跌 40% 敢不敢加仓"拷问）+ 证伪条件清单（挂到关键变量）+ 季度跟踪清单（指标 + 警戒线）+ **用户初判对照**（Phase 0 记录的用户初判 vs 最终结论，分歧点明说）+ 与上次结论对比（若存在 decision-log，diff 模式）。
12. **附录**：数据底稿摘要、全部数据来源与截止日期及来源等级（A/B/C）、**入口校验结果摘要（validate_data，含警告与竞对是否跳过双源核对的披露）**、数字校验结果摘要、术语速查表、免责声明。

## 核验强度徽章（首屏强制，verify_report 门禁项）

生成方式（**禁止手写，手写会被门禁逮住**）：

```
python3 scripts/verification_strength.py --financials data/financials_<公司>.json \
    --manifest data/manifest.json [--cycle-sensitive] \
    -o data/verification_strength.json --emit-html
```

把 `--emit-html` 输出的 `<div class="verification-strength" …>` 原样粘到首屏决策卡内（模板占位符 `{{核验强度徽章}}`）。`verify_report.py` 会把徽章的 `data-*` 属性与 `verification_strength.json` 逐字段比对，不一致、缺属性、或删掉"未经原文机器逐字比对"声明，均判交付失败。

**为什么必须与结论同屏，不能只写在附录**：交付时打印的"校验通过（退出码 0）"实际只保证「报告 = 底稿」。它不保证底稿为真——三表勾稽只在科目齐备的年份执行（GOOG/TSM 曾以 18% 覆盖率通过校验），命门科目双源核对是分析方自填区块、来源官方性靠关键词匹配判定，10 年数据窗口对银行/大宗商品不足一轮完整信用周期。**绿色勾给出的置信度高于它实际的保证范围，这才是最危险的地方。**

三项指标与分级：

| 指标 | full | partial | weak |
|---|---|---|---|
| 取证覆盖率（一般企业=三表勾稽；金融类=资产/权益 + 贷款质量三件套） | ≥90% | 60~90% | <60% |
| 命门科目原文登记 | 最近 3 年齐备且全为官方原文 | 部分或含降级来源 | 无 crosscheck |
| 数据窗口 | 达年限要求（金融/强周期 15 年，其余 10 年）**且**覆盖过至少一个系统性压力年 | 覆盖压力年但年限不足 | 未覆盖任何压力年 |

总评：三项 full → A；含 partial 无 weak → B；含 weak/none → C。**C 级不阻断交付**（它是要被披露的事实，不是要被拦住的错误），但档位判定须从严并在首屏说明。归档实测：A=7、B=3、C=1（台积电，勾稽 18% + 原文登记 partial，与仓库自标的"底稿待重建"一致）。

窗口内不含任何系统性压力年时，该标的的"历史最差"并未被观测到——**周期正常化的均值口径与悲观情景的历史锚都不成立**，此时正常化基期与悲观情景必须改用行业基率或同类死亡案例。

## 图表规范

- 用 ECharts；配色统一（主色深蓝 #1a3a5c，对比色琥珀 #d97706，竞对用灰色系，A 公司永远用主色突出）。
- 每张图必须有：洞察式标题、数据来源脚注（含来源等级）、竞对对比（凡适用）。
- 跨市场竞对对比图，脚注必须注明口径差异：会计准则（CAS/IFRS/US-GAAP）、财年错位（如苹果 9 月财年）、币种与汇率换算基准（取自底稿口径注册表字段）。
- 数字格式：亿元/百万美元按上市地惯例；百分比保留 1 位小数。
- 优先图型：趋势用折线、结构用堆叠、对比用分组柱、评分用雷达、估值区间用横向浮动条。

## 质量红线

- 摘要页的每个结论都能在正文找到数据支撑。
- **关键结论数字必须用 vnum 溯源标签包裹**：`<span class="vnum" data-src="<底稿文件>" data-path="<取值路径>" data-fmt="<格式>">显示值</span>`，供 `scripts/verify_report.py` 自动比对（格式定义见脚本头注释）。覆盖范围至少包括：摘要页全部数字、估值区间与安全边际、CAGR/ROIC/ROIIC 等长期指标、市场快照卡。
- **图表 series 必须带 vchart 锚点且数据取自 metrics 底稿的 `chart_series` 区块**：在每条 series 的 data 数组上方紧跟注释 `/*<!-- vchart src=metrics_X.json path=chart_series.net_margin scale=100 -->*/`（scale=100 用于小数→百分数）。禁止手抄数组进 HTML——图表数据唯一来源是 compute_metrics 输出的 chart_series。锚点供 verify_report.py 校验，能逮住位数错误与顺序错位。
- **ECharts 键名陷阱：radar 用 `value`，bar/line 用 `data`**。radar 系列的数据项写成 `data:` 时不会报错，坐标轴与图例照常渲染，但所有数据点塌缩到圆心，肉眼看就是"图表数据是空的"。写雷达图（三大师评分、资本配置评分卡）时必须用 `value: [...]`。verify_report.py 已内置守卫，但生成时就写对可省一轮返工。
- 报告中每个关键数字都能溯源到 `data/` 底稿；交付前必须通过数字校验脚本（见 SKILL.md Phase 5 第 6 步），无法溯源的数字删除或改为定性表述。
- **定性论断也要挂证据（防幻觉的最后防线）**：影响结论的定性判断（如"管理层言行一致""转换成本高""定价权强"）必须在句末标注证据指针 `[E:<manifest文件编号或文件名>]`，指向 manifest 中登记的证据文件（年报附注页码、电话会纪要、研报事实段）。规则：① 五维分析每一维至少 3 条关键论断带指针；② 大师评估中引用的事实必须能在 Phase 1~4 产物中找到原文；③ 红队抽查 5 条带指针论断核对原文，任一条查无实据 → 该维度结论降级并在报告标注。无证据可挂的论断只能写成"推断"并说明推断链条。
- 报告中不出现"可能、大概、似乎"堆砌的和稀泥段落；不确定就明说"此处证据不足，置信度低"。
- C 级来源（网络兜底）的信息不得作为核心结论的唯一依据，引用时必须带链接。
- 免责声明固定文案：本报告由分析工具生成，仅供研究参考，不构成任何投资建议。市场有风险，投资需谨慎。
