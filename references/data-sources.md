# 数据源登记与能力矩阵（Phase 1 前置）

## 核心原则：本 skill 不绑定任何单一数据源

**唯一契约是 `data/*.json` 底稿**，不是某个接口。计算层（`scripts/` 下 9 个脚本）零网络依赖——只 import `json`/`math`/`argparse` 等标准库，全部消费底稿 JSON。取数在 Agent 侧、计算在脚本侧，中间用底稿解耦。

这不是设计洁癖，是被现实逼出来的：招行年报是图片版 PDF、腾讯接口返港币需按期末汇率反推、A 股接口没有 capex 独立科目、银行缺不良/拨备/NIM。**没有任何单一源能覆盖十年×三市场×十类商业模式**，所以流程必须接受"多源拼装 + 双源核对 + A/B/C 分级"。

推论有三条，都是硬约束：

1. **换源不改脚本**。新源只要能填出底稿 schema，计算与校验链路完全复用。
2. **缺源不等于不能分析**，但必须明确降级并承担工作量（见下方缺口应对）。
3. **同一公司用不同源，数字可能不同**。港币折算差约 10%、现金口径宽窄差（PDD 接口 710 亿 vs 披露 630 亿）都是实证过的。所以 `manifest.json` 必须登记本次实际用了哪些源。

## 已实证的缺口与应对（换源前先读这张表）

| 缺口 | 影响 | 应对 |
|---|---|---|
| **A股 capex / D&A 无独立科目**（实测 `finance --type cashflow` 只给 `NetInvestCashFlow`）| Owner Earnings 与维持性 capex 拆分算不准，直接影响估值基期 | 从年报现金流量表原文补（巨潮 PDF），或研报历史序列（B 级）；补不到时 `compute_metrics` 会用 D&A 兜底并进 warnings，**必须在报告披露** |
| **A股 TotalAssets 缺失** | 三表勾稽跑不了 | 用 `TotalLiability + TotalShareholderEquity` 推导（伊利实测误差 <0.1%）|
| **A股权益口径** | 勾稽失败 | 必须用 `TotalShareholderEquity`（含少数股东），**不能**用 `SEWithoutMI`（归母）。但回报率与估值只认归母，底稿另存 `roe_parent`/`bvps_parent` |
| **银行专属科目全缺**（不良/拨备/NIM/资本充足率）| 银行管道无法建稿 | 标普信评评级报告附录（B 级，含连续 5 年完整指标表）+ 年报披露转引（C 级需双源）；或用 ifind 补 |
| **港股营收字段可能为空**（腾讯 `OperatingRevenue`/`Sales` 均无）| 收入序列断裂 | 财报手工补并标 A 级 |
| **港股接口为港币口径** | 与披露人民币值差约 10% | 用「接口值 ÷ 当年末汇率」反推，年报公告交叉验证误差 <1%，`fx_basis` 必填 |
| **美股早年 capex 标签缺失**（NVDA FY2016-2021）| 十年序列断裂 | 回 10-K 原文合并现金流量表补，原文存档 `data/filings/` |

## 行情复权口径纪律（P0-2，三口径使用矩阵）

> 来源：OBS-000895-02 机器实证（双汇 61 根月K反推：东财 fqt=1 为**等差（减法）复权**，
> P_raw − P_adj = 累计分红，序列比值 +45.61% vs 真实总回报 +18.70%，**高估 26.9pct**）
> + OBS-600660-02 家族关联（福耀 pb_trough 前复权×当年 BPS，PB 低估 15-20%）。
> 三级危害：荒谬值（当场可见）→ 叙事掩盖 → **看似合理**（最危险：福耀/海控"亿×10"
> 错位后数字仍在常识区间，直接进叙事不被察觉）。

| 口径 | 东财参数 | 语义 | **唯一合法用途** | 禁止用途 |
|---|---|---|---|---|
| 等比后复权 | `fqt=2` | 乘法调整，分红再投资，跨期可比 | **收益/总回报计算**（actual_Ny_total_return 一律用它） | — |
| 不复权 | `fqt=0` | 当年真实成交价 | **触及检验、内在价值比较、与当年披露 BPS/股价运算** | 长区间收益计算 |
| 等差前复权 | `fqt=1` | 减法调整（P_raw − 累计分红） | **仅形态展示、除息序列反推** | **严禁**用于收益计算（高估）、触及检验（前复权价随分红整体下移产生虚假触及） |

三条配套纪律：

1. **`answer.json` 的 `price_basis.source` 强制声明口径**（含抓取渠道与日期）——收益断言的
   可复现性依赖它；缺声明的事后回报值无法事后审计（第一批茅台/福耀先例核对即卡在这里，
   见下）。runner 对含 `actual_*_total_return` 数值但缺 `price_basis` 的 answer 出咨询提示。
2. **自检方法：后复权无基准漂移**——同一历史值跨批次抓取应完全一致（双汇 fqt=2 的
   2019-06-28 值 388.26 双批次一致，实证通过）。前复权因子随每次分红整体重算，同一答案
   跨批次**不可比**，只能当次自洽。
3. **A/H 存在多市场价**时，触及检验用对应市场的不复权价，收益计算用对应市场后复权价，
   不得混用两个市场的复权序列。

**第一批先例核对（2026-09-09 补做，记 observations.md OBS-2015-08-06）**：
回放价口径（fqt=0 不复权）第一批四案全部正确（茅台 195.37 / 福耀 22.78 / 康美 22.36 /
海控已在 snapshot 声明）——触及检验无污染。但**收益值口径未声明且不可精确复现**：
茅台记录 5y=8.062x / 3y=2.375x，福耀 3y=1.856x；用腾讯 hfq 月K（与东财 fqt=2 交叉验证
过的等比渠道）按回放日锚重算为 8.552x / 2.642x / 1.922x——记录值系统性偏低 0.8%~11%，
锚定扫描显示与「回放日前一个月末」（2015-07-31 / 2018-07-31）起点一致（差 <1.5%），
疑取数窗口月末对齐缺陷，**非复权方法错误**。两案档位结论均不翻（茅台官方"约 8 倍"
与 8.55x 同量级，假阴性判定不变；福耀 3y 回报非档位闸门）。茅台/福耀 answer.json 已按
事后核对性质补录 price_basis（记录值未动）。

## 强制动作

1. **Phase 1 开始前跑一次源探测**：`python3 scripts/check_data_sources.py`。输出本机可用源、覆盖能力与缺口应对提示。缺推荐源时脚本会给出安装引导——**不要静默降级**，让分析师知道自己将付出多少手工成本。
2. **`manifest.json` 登记 `data_sources`**：数组，逐项写 `{"source": "westock-data", "version": "1.0.6", "used_for": ["三表","行情","一致预期"], "level": "A"}`。复现与复盘校准都依赖它——同一公司换源重跑，数字对不上时第一件事就是查这里。
3. **命门科目双源核对不可用接口自证**：收入/归母净利/经营现金流/总股本最近 3 年必须与官方披露原文（EDGAR/巨潮/披露易）核对。**接口 ≠ 原文**，即使接口是 A 级。

   执行方式按市场分两条路，跑 `scripts/crosscheck_official.py`：

   | 市场 | 官方源形态 | 核对方式 |
   |---|---|---|
   | 美股 | EDGAR companyfacts（XBRL，结构化、免鉴权）| **机器核对**：`--companyfacts <file>` 自动取官方值逐年比对，`--write` 回写 crosscheck。不经人手转录 |
   | A股 | 巨潮年报 PDF（非结构化）| **人工转录 + `--audit` 体检完整性** |
   | 港股 | 披露易年报 PDF（非结构化）| 同上 |

   为什么美股要单独做机器核对：手抄进 `crosscheck` 的值与手填进 `annual` 的值来自同一次阅读，比对的是"我抄得一致吗"而不是"接口对不对"——**同人同眼，看错年份不会被发现**。EDGAR 有结构化 XBRL，这条路能真正独立取数，就不该退回人工。

   **A4 规则（2026-09-02 实测后加）**：强制科目的官方值为空＝该科目实际未被交叉核对，**直接报错**而非告警。起源：此前"官方值缺失"仅告警，导致 11 个归档案例中 6 个从未核对 `shares_diluted`——而它是 `eps`/`oe_ps`/每股内在价值的分母，错了会线性缩放整个估值与安全边际。确无法取得时写 `crosscheck_exempt` 显式豁免，让缺口进入报告披露而不是消失在告警流里。

   **实测逮到的真实缺陷**：中国平安底稿 2014-2023 的 `shares_diluted` 填的是 **H 股股本 8890 百万股**，2024 起改用总股本 18210——导致 `evps` 在 2023→2024 从 148.75 机械腰斩到 78.13，看起来像内含价值崩了一半，实为口径断裂。已全期统一为总股本 18280，修正后 2023 evps=72.34，与平安年报披露吻合（市值反推 1010770/55.82=18108 亦一致）。该案估值只用 2025 evps 与前瞻 EV，投资结论不受影响，但十年每股趋势图此前是错的。

## 新增数据源的接入清单

想接第四个源时按此走，不要直接改脚本：

1. 确认它能填的底稿字段，对照 `compute_metrics.py` 头注释的 schema；
2. 在上方能力矩阵加一行，写清授权模式与覆盖范围；
3. 在 `check_data_sources.py` 的 `SOURCES` 注册探测方式；
4. 跑一个真实公司全流程，把踩坑固化到 [data-sourcing.md](data-sourcing.md)；
5. **不要**为某个源在脚本里加分支——若发现非改不可，说明底稿 schema 抽象漏了，应该改 schema。
